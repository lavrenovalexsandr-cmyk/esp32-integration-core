# ESP32 OTA Manager для Home Assistant

Пользовательская интеграция Home Assistant для обнаружения ESP32-устройств через MQTT, отображения их состояния и управления OTA-обновлением прошивки, перезагрузкой и полным сбросом настроек.

## Содержимое репозитория

- `custom_components/esp32_ota` — интеграция Home Assistant и сервисы управления устройствами.

Панель управления **ESP32 OTA Manager** входит в эту интеграцию и появляется в боковом меню Home Assistant. Отдельные Lovelace-карточки и второй HACS-репозиторий не требуются.

## Требования

- Home Assistant с настроенной и подключённой официальной интеграцией MQTT.
- ESP32 прошивка, реализующая соответствующие MQTT-топики идентификации устройства и OTA.
- Для команд перезагрузки и полного сброса требуется поддержка топиков `system/restart` и `system/factory_reset` в установленной прошивке.

## Идентификация шлюза в Home Assistant

Все ESP32-интеграции используют единый идентификатор устройства шлюза в Home Assistant Device Registry:

```python
identifiers={("esp32", device_id)}
```

- `esp32` — общий namespace платформы ESP32, не домен конкретной интеграции.
- `device_id` — стабильный ID шлюза из MQTT identity.
- **OTA Manager отвечает за первоначальную регистрацию шлюза и задание его пользовательского имени** при первом обнаружении устройства в Home Assistant.
- Пользовательское имя хранится в Home Assistant Device Registry в поле `name_by_user` и является единственным общим отображаемым именем шлюза для всех ESP32-интеграций.
- Имя из MQTT identity (`name`) — техническое исходное имя устройства и резервное значение, если `name_by_user` ещё не задано. Оно не должно перезаписывать пользовательское имя.
- Остальные ESP32-интеграции, включая Xiaomi Sensor Manager, должны читать `name_by_user` из общей записи Device Registry и не должны заводить собственное пользовательское имя шлюза.

Переименование шлюза выполняется средствами Home Assistant в карточке устройства (**Настройки → Устройства и службы → Устройства → ESP32 → Изменить устройство**). После этого новое имя должно отображаться во всех интеграциях, использующих общий identifier. MQTT identity и стабильный `device_id` при переименовании не меняются.

**Требование к реализации `esp32_ota`:** при обновлении записи шлюза интеграция обязана сохранять `name_by_user`. Вызов `async_get_or_create` с именем из MQTT допустим для создания/обновления исходных данных устройства, но не должен приводить к потере имени, назначенного пользователем.

**Миграция в этой ветке:** при первом MQTT-сообщении от шлюза интеграция автоматически заменяет старый identifier на общий, сохраняя существующую запись устройства и связанные с ней сущности. Если общий identifier уже принадлежит другой записи HA, автоматическое изменение пропускается и в лог записывается ошибка — такие дубли нельзя объединять вслепую. Обновление `esp32_ota` следует выполнить до установки/обновления других интеграций, использующих новый namespace. Домен интеграции и сервисов `esp32_ota` остаётся без изменений.

Другие ESP32-интеграции должны использовать тот же идентификатор и получать identity непосредственно из общего MQTT-контракта. Им нельзя импортировать код `esp32_ota` или требовать её установки. Интеграции могут независимо добавлять свои сущности к одному устройству шлюза.
## Доступность устройства

Интеграция отдельно отслеживает MQTT availability по топику `esp32/<DEVICE_ID>/availability` (retained `online` / `offline`). OTA-статус не используется для определения доступности. При неожиданном отключении ESP32 брокер публикует retained `offline` через MQTT Last Will, настроенный в `platform_ha` Core. Панель **ESP32 OTA** показывает «Не в сети» независимо от последнего результата обновления.

## Установка через HACS

1. Откройте **HACS → Интеграции**.
2. Откройте меню в правом верхнем углу и выберите **Пользовательские репозитории**.
3. Добавьте репозиторий:
   `https://github.com/lavrenovalexsandr-cmyk/esp32-integration-core`
4. В качестве категории выберите **Integration** и подтвердите добавление.
5. Найдите **ESP32 OTA Manager** в HACS и установите интеграцию.
6. Перезапустите Home Assistant.
7. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и добавьте **ESP32 OTA Manager**.
8. Откройте панель **ESP32 OTA** в боковом меню Home Assistant.

После установки через HACS файлы интеграции будут размещены в `custom_components/esp32_ota`. При выходе новых версий обновление можно выполнять из HACS.

### Ручная установка

Если HACS не используется, скопируйте каталог `custom_components/esp32_ota` в `<HA config>/custom_components/esp32_ota`, перезапустите Home Assistant и добавьте интеграцию через **Настройки → Устройства и службы → Добавить интеграцию**.

## Панель управления Home Assistant

Панель **ESP32 OTA** поставляется вместе с интеграцией, регистрируется в боковом меню Home Assistant и доступна администраторам. Она объединяет выбор ESP32, MQTT availability, текущий OTA-статус и прогресс, запуск OTA-обновления, сохранение GitHub-токена, перезагрузку и полный сброс. Панель вызывает сервисы интеграции и не публикует MQTT напрямую.

Для отображения имени панели использует `name_by_user` из общей записи Device Registry с идентификатором `("esp32", device_id)`; если пользовательское имя не задано, используется исходное имя устройства.

## Сервисы Home Assistant

Интеграция предоставляет следующие сервисы домена `esp32_ota`:

| Сервис | Параметры | Назначение |
|---|---|---|
| `esp32_ota.update` | `device_id`, `url`, необязательно `token` | Запуск OTA-обновления выбранного устройства |
| `esp32_ota.restart` | `device_id` | Обычная перезагрузка выбранного ESP32 |
| `esp32_ota.factory_reset` | `device_id` | Полный сброс пользовательских настроек выбранного ESP32 |
| `esp32_ota.save_token` | `token` | Сохранение GitHub-токена |

Для сервисов управления `device_id` — 12-значный аппаратный ID ESP32 в шестнадцатеричном формате. Устройство должно быть обнаружено интеграцией по MQTT.

## MQTT-протокол

Интеграция обнаруживает устройства по retained-сообщениям с их идентификацией:

- Топик: `esp32/<12-uppercase-hex-id>/device/info`
- Пример содержимого:

```json
{"id":"AABBCCDDEEFF","name":"Kitchen","model":"ESP32-C3"}
```

### OTA-обновление

Команда OTA-обновления (QoS 1, без retained):

- Топик: `esp32/<id>/ota/update`
- Содержимое:

```json
{"url":"https://.../firmware.bin","github_token":"<optional>"}
```

Статус OTA-обновления:

- Топик: `esp32/<id>/ota/status`
- Пример содержимого:

```json
{"status":"online|downloading|installing|rebooting|success|error","progress":0,"message":"..."}
```

### Команды управления устройством

Команды отправляются адресно выбранному ESP32, с QoS 1 и без retained:

| Действие | MQTT-топик | Payload |
|---|---|---|
| Перезагрузка | `esp32/<id>/system/restart` | `1` |
| Полный сброс | `esp32/<id>/system/factory_reset` | `1` |

Обычная перезагрузка не должна изменять настройки устройства. Factory Reset должен обрабатываться прошивкой и удалять пользовательские настройки в соответствии с её реализацией. Интеграция Home Assistant отправляет команду, но сама не очищает память ESP32. Убедитесь, что установленная версия прошивки поддерживает эти MQTT-команды.

При успешной отправке сервис подтверждает публикацию команды в MQTT; это не является подтверждением завершения перезагрузки или сброса самим устройством.

Принимающая часть OTA на стороне прошивки поддерживается в отдельном проекте ESP32: [esp32_mqtt_xiaomi_lywsd03](https://github.com/lavrenovalexsandr-cmyk/esp32-firmware-xiaomi-lywsd03). Прошивка загружает файл по HTTPS, записывает его в неактивный OTA-раздел и передаёт состояние обновления через MQTT.

## GitHub-токен для приватных релизов

Панель **ESP32 OTA** позволяет указать необязательный GitHub-токен. Интеграция может сохранить его в `secrets.yaml` Home Assistant под именем `esp32_ota_github_token`.

При сохранении существующие строки и комментарии файла не удаляются. Файл записывается атомарно с правами доступа только для владельца. Токен, введённый непосредственно в форме обновления, имеет приоритет над сохранённым токеном для этого запроса.

Токен передаётся только API-адресам GitHub. Его нельзя пересылать на внешние CDN-серверы, с которых загружается файл прошивки.
